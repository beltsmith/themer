## Caveats

- Shares reflect what nvim-treesitter's queries *paint*, not language semantics: e.g. bash `constant` is nvim's ALL_CAPS-variable heuristic; C/Go/Lua use `property` where others use `variable.member`; Rust/C have no `function.method.call`; Java has no plain `function.call`. Use the `role` level for cross-language comparisons.
- elisp uses the sparse upstream Wilfred/tree-sitter-elisp query (no call/symbol captures), so ~40% of its ink is `default`; pooled `default` is almost entirely elisp.
- Injections are not run: doc-comment markup (JSDoc/LuaCATS/rustdoc), regex internals, printf formats, and embedded languages stay painted as their host comment/string.
- Comment/docstring share is very corpus-dependent (requests/flask docstrings, neovim LuaCATS, rustdoc, javadoc). Treat comment/string char shares as +/- 10pp across codebases; token shares and per-screen counts for code tokens are more stable.
- Pooled = unweighted mean of 10 languages (JS and TS counted separately).
