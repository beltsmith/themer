# Lexical recoverability of roles

Generated by `harness/recoverability.py`. Per language, multinomial logistic regression on lexical features only (token shape, exact text if among the language's 300 most frequent segment texts, previous/next non-whitespace character, previous segment text if top-300, shape x prev/next char). Unit = visible token segment (role_tokens.py; punctuation counts). GroupKFold(5) by file, out-of-fold. **Recoverability = recall.** ALL = unweighted mean over languages excluding elisp (sparse query, 41% `default`); `n_langs` = languages where the role occurs.

## Caveats

- Labels are nvim-treesitter's paint, so recoverability is 'how much of what the query knows is visible in the glyphs'. Roles the query cannot see either (e.g. variable.def needs locals; field vs variable at a use site) are bounded by that.
- The top-300 vocabulary is computed on the whole language corpus (unsupervised counts, not labels), so closed classes are visible to every fold.
- One segment = one example, so long comments/strings and one-char punctuation weigh the same. Recall is per segment, not per character.
- A linear model with two conjunctions is a lower bound on lexical recoverability; a reader also sees wider context (indentation, the whole line).
- Closed classes are approximated by the top-300 texts, so rare keywords fall outside it (Rust `break`/`continue`, C `true`/`false`) and look like identifiers; a reader who knows the language would not make that error.
- Some labels are themselves lexical rules in the queries (ALL_CAPS identifier -> @constant in Python/Rust/C/Java/Lua/bash; `self`/`this` -> variable.builtin), so their recoverability is high by construction. See corpus_findings.md for declared-constant shape.
- keyword.exit here is the refined role (exit words only); see out/role_stats.md.
