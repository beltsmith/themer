# Reader site

A small web server for the reader standard. It serves `research/` as pages (Markdown is
rendered, YAML/CSV/JSON is shown as text, the render grids as they are) and the timed search
task at `/task`. Task reports are stored in an S3 bucket, one JSON object per participant.

| Route | What |
|---|---|
| `/` | Index |
| `/research/...` | Anything under `research/` except `data/` and dotfiles |
| `/task` | `research/out/renders/tasks.html` |
| `POST /api/reports` | Validates a task report and writes it to S3 |
| `/healthz` | Liveness check |

## The task page

`tasks.html` is generated by `research/harness/render.py`. When served over HTTP it ends with
**Submit results** (plus **Download results** as a fallback). Opened from disk it only offers
the download, as before. Each report carries `trials_version`, the first 12 hex digits of the
SHA-256 of the trial set, so reports from different generations of the page stay apart.
Regenerating `tasks.html` with an unchanged `render.py` and corpus gives the same version.

A stored report has the fields the page sends (`trials_version`, `started`, `finished`,
`results` in the `task_results.json` format, `client` with viewport, device pixel ratio,
colour depth, gamut and time zone, and an optional free-text `note`), plus `id`, `received`
and `user_agent` added by the server. The IP address isn't stored. Keys are
`$S3_PREFIX<trials_version>/<id>.json`, and the key is always chosen by the server.

## Run locally

```sh
cd server
uv run uvicorn app:app --reload        # http://127.0.0.1:8000; reports go to ./reports/
uv run pytest -q tests
```

## Configuration

| Variable | Default | |
|---|---|---|
| `S3_BUCKET` | unset | Bucket for reports. Unset: write to `REPORTS_DIR` |
| `S3_PREFIX` | `task-reports/` | Key prefix |
| `S3_ENDPOINT_URL` | unset | For S3-compatible stores (MinIO, Cloudflare R2, ...) |
| `AWS_REGION`, credentials | | The usual boto3 chain: environment, instance/task role, ... |
| `REPORTS_DIR` | `./reports` | Local fallback |
| `THEMER_RESEARCH_DIR` | `../research` | Directory to serve |

## Deploy

Build from the repository root (the image contains `research/` without `data/`):

```sh
docker build -f server/Dockerfile -t reader-site .
docker run -p 8000:8000 -e S3_BUCKET=my-reader-reports -e AWS_REGION=eu-west-2 reader-site
```

Run it behind a TLS-terminating proxy or load balancer. Rebuild the image after regenerating
`tasks.html` or changing the documents.

The bucket should block all public access. The server needs only `s3:PutObject` on the
prefix:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": "s3:PutObject",
    "Resource": "arn:aws:s3:::my-reader-reports/task-reports/*"
  }]
}
```

`POST /api/reports` is open to anyone. Bodies are capped at 64 KB and must match the report
shape, but there is no rate limiting; add it at the proxy if needed.

## Collect reports

```sh
aws s3 sync s3://my-reader-reports/task-reports/ research/out/task_reports/
```

Each file's `results` list has the same format as `research/out/task_results.json`.
